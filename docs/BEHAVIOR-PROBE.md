# 响应行为探测：可行性与边界

## 结论

可以增加人工触发的探测：向指定模型发送固定短提示，记录实际回复、耗时、错误和可获得的模型/路由元数据，再与同样条件下的历史样本比较。

`ciallo` 可以是一个提示样本，但它的某种特定回答不是模型“降智”或被替换的可靠证据。系统提示词、采样随机性、语言、版本、路由策略和安全设置都会改变回复；代理返回的 model 名称也不是身份认证。

## 最小合理范围

- 用户明确选择模型后，手动点击一次执行；界面提前说明会消耗额度。不后台轮询、不自动遍历全部账号/模型。
- 使用独立的空上下文，仅发送公开固定测试提示，不携带当前项目或私人对话。
- 把单条返回显示为“响应样本/行为差异”，而非“真模型/假模型”或确定的降智判决。
- 对同一模型配置使用固定的一小组指令遵循、格式约束和可验证基础题，按题目给出结果，并区分失败、超时与答错。
- 保留运行条件和时间，支持本地比较；不能把不同提示或路由的结果硬作能力变化。
- 不把模型调用凭据发送到前端，不向公开仓库上传真实响应、账号或路由数据。
